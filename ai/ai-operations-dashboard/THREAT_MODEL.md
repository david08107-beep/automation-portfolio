# Threat model — AI OS and proposed integrated workspace

Scope: owned AI OS source and local synthetic tests only. No penetration test of GitHub, hosting, authentication providers, or other third-party infrastructure. Review date: October 8, 2026. Companion: [integration plan](INTEGRATION_PLAN.md).

Assets: prepared content, user/workspace identity, profiles, external accounts/tokens, approvals, external resources, durable audit history. Actors: legitimate member, curious or malicious member, external attacker, compromised browser/dependency/provider, malicious retrieved content or model output. Trust boundaries: browser↔backend, backend↔identity/provider, worker↔tools, workspace↔workspace, source/build↔deployment, untrusted content↔rendered UI. Current demo has only browser state and fictional scheduler; its displayed Dave identity is not authentication.

| Threat / abuse case | Current implemented safeguard | Required integrated-system mitigation / validation |
| --- | --- | --- |
| Request, draft or stored-history XSS | Escaped templates, textContent for dialog content, text-only downloads; hostile input/storage browser checks | Server validation, restrictive CSP/security headers, audited rich-text sanitization if added. XSS remains able to access same-origin local data; no real secrets belong there. |
| Tampered storage adds privileged identities, tokens or policy | Restored domain fields are allowlisted; unknown metadata is discarded; validated preferences and workflow invariants; bounded payloads | Server authoritative identity/permissions and explicit, scoped demo import. Local JSON is never trusted audit/consent. |
| Oversized input/state freezes UI or exhausts storage | 500-character requests; 100,000-character results; restored raw state 10M chars, max 500 workflows/20,000 activity events/10,000 timeline entries per workflow/1,000 draft versions. Invalid state retains original snapshot and warns | Server byte limits, pagination, quotas and rate limits. Runtime histories still grow until storage quota failure; caps on restoration are not a full availability defense. |
| Stale or substituted approval executes different text | Confirmation captures exact result; changes during preview block local completion; terminal transition rejects duplicates; no external execution code | Immutable result version plus exact action, expiry and revision; transactional server approval and one-use action. Browser equality checks are UX safeguards, bypassable by a compromised client. |
| Multiple tabs or retried jobs duplicate external action | Best-effort snapshot guard pauses stale tabs; duplicate local complete decisions do not add events | Server transactions, unique action/idempotency keys, worker leases, provider idempotency and reconciliation for unknown outcomes. |
| Member reads another user's/workspace's drafts/connections | Not implemented; all local browser users can read or alter local state | Server membership and resource ownership checks on every API/job/export; tenant-scoped database/storage policies; negative authorization tests. |
| Credential theft, OAuth login CSRF or redirect hijacking | No authentication/OAuth/tokens implemented; no passwords/MFA codes collected | Established OIDC provider; managed secure sessions; CSRF/origin checks; one-use state, nonce, PKCE, exact callbacks; backend-only encrypted tokens; token rotation/revoke tests. |
| Overbroad scope, disconnected account still executes, confused deputy | No external accounts/actions | Incremental minimum consent, bind action to workspace/connection/provider account, server capability checks, immediate disconnection effects and in-flight reconciliation. |
| Prompt injection from third-party content induces send/share/publish | No models or real data; local completion never sends or modifies records | Treat content as data; scoped tools, sandboxing/SSRF controls, deterministic authorization outside prompts, contextual approval of every external action. |
| Sensitive content leaks into logs/export/clipboard | App has no content console logging; draft-only text export; explicit download/copy. Synthetic tests check unknown metadata not exported/logged | Structured redaction, scoped export authorization, user consent for confidential exports, retention/deletion controls. User-entered draft text is deliberately exported verbatim, not automatically classified or redacted. |
| Supply-chain/dev-server compromise | Lockfile installation; Vite patch upgrade; registry advisory audit | CI dependency/secret scanning, trusted build, minimal deployed artifacts, restricted dev servers, update ownership. Advisory and pattern scans have blind spots. |
| Audit repudiation, deletion or forged actor | Local edit/action events only, mutable client timestamps/state | Server-authenticated actors/timestamps, access-restricted durable audit, correlation and action/resource version references, retention policy. |

## Validation matrix

Implemented local tests cover unsafe command and restored-content rendering, malformed/inconsistent storage, unknown-field dropping, draft size limits, exact-preview approval changes, duplicate terminal decisions, tab conflicts, export contents and clipboard failure. Browser checks run desktop/mobile Chromium and existing accessibility checks.

Authentication/session, cross-user/workspace isolation, OAuth callback/state/refresh/revocation, encryption, production headers and server rate limits are **not implemented and not tested**. Testing them is blocked until an authorized backend/provider exists. A fictional two-tenant browser fixture is not a substitute for real authorization tests.

Dependency audit before remediation reported Vite high-severity and esbuild low-severity development-tool advisories. Final versions and after-remediation counts are recorded in SECURITY_REVIEW.md. Pattern-based secret checks report only file/rule findings, never matched values. No credentials are copied from the environment into artifacts. Tests use synthetic markers and local resources.

Residual risk is high for real-user use because the application has no backend trust boundary. It is suitable only as a fictional portfolio demo under the stated scope. Stop before connecting real accounts or importing real user data. The integrated-system security assessment, remediation and retesting are mandatory release gates, not optional certification badges.
